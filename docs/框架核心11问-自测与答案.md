## 第一梯队：面试必考，要能白板写、口头讲

### Q1 `scope="session"` 和不写 scope 有什么区别？为什么 client 用 session、auth_client 用 function？

**答：**

| 写法 | 含义 |
|---|---|
| 不写 scope | 默认 `function`，**每条用例**都重新执行一次 |
| `scope="session"` | 整个测试过程**只执行一次** |

- `client` 用 session：HTTP 连接可以复用，29 条用例不用建 29 个连接；
  更重要的是变量池 `ctx` 必须是 session 级，否则 extract 存的值下一条取不到。
- `auth_client` 用 function：它给 client 加了 `Authorization` 头，
  **每条用例用完必须摘掉**（`remove_header`），否则下一条"不带 token"的用例会被污染。

**记忆点**：共享的用 session，会改状态的用 function。
**实验**：把 `conftest.py` 里 `remove_header` 那行注释掉，跑 `test_auth.py`，
"不带 token 应返回 401" 会变成 200 != 401 —— 亲眼见过一次就忘不掉。

### Q2 `conftest.py` 是干嘛的？

**答**：不是"前后置处理器"，它是 **fixture 的公共存放处**。

- 放在项目根的 `conftest.py`，下面所有 `testcases/` 里的用例都能直接用，**不用 import**
- 里面还能放 pytest 的钩子：`pytest_addoption`（注册命令行参数）、
  `pytest_configure`（跑之前切环境）、`pytest_report_header`（输出加一行）

**记忆点**：conftest = 全项目共享的"后勤处"，fixture 和钩子都住这儿。

---

### Q3 为什么用例里只要写个参数名 `client`，pytest 就自动给你？

**答**：这叫**依赖注入**，和"继承"没有关系（client 是你自己写的类，用例没继承它）。

```
用例参数名写 client → pytest 去 conftest 找同名的 fixture 函数 → 执行它 → yield 出来的值传给这个参数
```

**记忆点**：像点菜 —— 你报菜名（参数名），后厨（conftest）做好端上来。
**实验**：把参数名改成 `client2`，pytest 会报 `fixture 'client2' not found`，
证明它是**按名字找**的，不是继承来的。

### Q4 `run_case()` 内部固定做哪 5 步？

**答**：

| 步 | 干什么 |
|---|---|
| 1 渲染 | `${token}` 换成真值（在 `client.request()` 里做） |
| 2 发请求 | 拼上 base_url 发出去 |
| 3 断言状态码 | 通不通（`assert_status`） |
| 4 提取 + 登记 | extract 存变量、cleanup 登记待清理 |
| 5 断言字段 | 对不对（`assert_expect`） |

**记忆口诀**：先换变量 → 发出去 → 验通不通 → 存下要用的 → 验对不对

### Q5 yaml 里的 `${token}`，什么时候、被哪段代码换成真实值？

**答**：

- **时机**：**发请求前一刻**（不能更早 —— 那时 token 还没拿到）
- **代码**：`common/client.py` 的 `request()` 里

```python
if self.context:
    path = self.context.render(path)
    for key in ("params", "json", "headers"):
        ...
```

- **token 从哪来**：`conftest.py` 里 `autouse=True` 的 `init_context` 先登录一次，
  再 `ctx.set("token", token)` 塞进变量池

**记忆点**：登录 → 进池子 → 写 `${token}` → 发请求前才替换。
**实验**：yaml 里故意写 `${nope}`，跑一次看报错
`占位符 ${nope} 没有值。变量池里现在只有：['token', ...]`

## 第二梯队：要能讲清"为什么这么设计"

### Q6 extract 取不到值会怎样？为什么设计成报错而不是跳过？

**答**：`common/extractor.py` 里 `raise AssertionError("提取失败：表达式 xxx 没取到值...")`。

**为什么不能跳过**：静默跳过 → 后面用 `${product_id}` 的请求带着空值发出去 →
报 400/404。你看到的是"下一条用例挂了"，会去查下一条的参数、环境、接口，
**根本想不到根因是上一条没取到值**，排查成本翻十倍。

**记忆点**：收货必须验收，不签字后面全乱且查不出哪一环出的问题。

### Q7 想让标题每次跑都不一样，yaml 怎么写？框架怎么调到 Python 函数？

**答**：

```yaml
json:
  title: "auto-${random_str(8)}"     # 也可用 ${gen_phone()} / ${timestamp()}
```

三步（`context.py` 的 `_lookup`）：

1. 正则发现占位符里**带括号** → 判定为函数调用
2. `getattr(functions, "random_str")` 去 `common/functions.py` 找这个函数
3. 找到就调用，找不到报"可用的有：xxx"

**记忆点**：只能调 `functions.py` 里定义的函数（安全），`${os.system(...)}` 调不到。

### Q8 `cleanup` 的登记为什么放在断言之前？

**答**：因为**断言失败会抛异常，函数立刻中断**，后面的代码一行都不会执行。

- 登记在断言后 → 断言一红，登记那行永远跑不到 → 商品残留在测试站
- 登记在断言前 → 先记账再办事，出事也记得清

配合 `conftest.py` 里 `autouse=True` 的 `cleanup_test_data`，收尾统一删。

---

### Q9 `expect_status` 和 `expect` 各验什么？只断言 200 会漏什么 bug？

**答**：

- `expect_status` → HTTP 状态码（**通不通**）
- `expect` → 响应内容字段（**对不对**）

只断言 200 会漏掉这些（全都返回 200/201 但业务是错的）：

- 查详情 id 传错，返回 200 但是**另一个商品**
- 创建商品返回 201，但 `price` 存成了 0
- 接口改版少返回一个字段，状态码照样 200

**记忆点**：通不通 vs 对不对，两个都得有。

### Q10 `"@length"` 为什么必须加引号？为什么不写 `$.length`？

**答**：

- **加引号**：`@` 在 yaml 里是保留字符，不加引号会解析报错
- **不写 `$.length`**：① 这个 jsonpath 库对单独的 `$` 返回 `False`，取不到整份响应；
  ② `$.length` 的字面意思是"取名为 length 的字段"，列表根本没有这个字段

`@` 是我们**自己约定的**"整体断言"标记，`asserter.py` 里判断 `startswith("@")` 就走整体分支。

### Q11 敲 `pytest --env=test` 后，从命令行到配置生效经过哪三步？

**答**：

| 步 | 位置 | 干什么 |
|---|---|---|
| 1 | `pytest_addoption` | 注册 `--env`（不注册会报 unrecognized arguments） |
| 2 | `pytest_configure` | 读出值 → `settings.configure(env)`；它在任何 fixture 之前跑 |
| 3 | `Config.configure` | 从 `config.yaml` 的 `environments[env]` 取出 base_url/timeout/user 覆盖上去 |

环境不存在 → `KeyError` → 转成 `pytest.UsageError` → 输出
`环境 [nope] 不存在。可用环境：['dev', 'test']`（友好提示，不是红字堆栈）。
